# 缓存一致性协议（Cache Coherence Protocols）

## 通用记法与数据结构

### **一致性消息**

它们在每个协议的 \<*protocol-name*\>-msg.sm 文件中描述。

| 消息              | 说明                                                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ACK/NACK**      | 对需要等待解决方向后再决定下一步动作的请求的肯定/否定确认。例如回写请求、独占请求。                                               |
| **GETS**          | 请求共享权限以满足 CPU 的加载或 IFetch。                                                                                                                                                               |
| **GETX**          | 请求独占访问。                                                                                                                                                                                                   |
| **INV**           | 失效请求。它可以由一致性协议自身触发，也可以由下一级缓存/目录触发，以强制包含关系，或为 DMA 访问触发回写以获取数据的最新副本。 |
| **PUTX**          | 请求回写缓存块。某些协议（例如 MOESI_CMP_directory）可能只用它来回写独占数据。                                                                                   |
| **PUTS**          | 请求回写处于共享状态的缓存块。                                                                                                                                                                           |
| **PUTO**          | 请求回写处于所有者状态的缓存块。                                                                                                                                                                            |
| **PUTO_Sharers** | 请求回写处于所有者状态、但该块还存在其他共享者的缓存块。                                                                                                                                       |
| **UNBLOCK**       | 用于对阻塞式协议解除下一级缓存/目录阻塞的消息。                                                                                                                                                           |

### **AccessPermissions（访问权限）**

它们与每个缓存块关联，决定允许对该块执行哪些操作。它与一致性
协议
状态紧密相关。

| 权限            | 说明                                                                                                                                                                                                                                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Invalid**     | 该缓存块无效。必须先（从内存层次结构中的其他位置）获取该块，才能执行加载/存储。对失效不做任何动作（也许发送 ACK）。对替换不做任何动作。关联的一致性协议状态是 I 或 NP，并且是每个协议中的稳定状态。 |
| **Busy**        | 待补充                                                                                                                                                                                                                                                                                                                         |
| **Read_Only**   | 只允许加载、回写、失效操作。在转换到其他某个状态之前不能执行存储。                                                                                                                                                                                           |
| **Read_Write**  | 允许加载、存储、回写、失效。通常表示该块是脏的。                                                                                                                                                                                                                             |

### 数据结构

  - **Message Buffer**：待补充
  - **TBE Table**：待补充
  - **Timer Table**：它维护基于地址的定时器映射。对
    每个目标地址，都可以关联一个超时值并加入
    Timer table。例如，MOESI_CMP_directory
    协议的 L1 缓存控制器实现就用该数据结构为不同的缓存块触发各自的超时。在内部，
    Timer Table 使用事件队列来调度超时。TimerTable
    支持基于轮询的接口 **isReady()**，
    用于检查是否发生了超时。地址上的超时可以用 **set()** 方法设置，
    用 **unset()** 方法移除。

  - **相关文件**：
      - src/mem/ruby/system/TimerTable.hh：声明
                TimerTable 类
      - src/mem/ruby/system/TimerTable.cc：TimerTable 类各方法的实现，
                处理地址与超时的设置、用事件
                队列调度事件。
